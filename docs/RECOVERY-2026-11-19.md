# November 19 radio demo and recovery

## Verified failures

Two changed boot IDs proved reboots, rather than just RDP disconnects. Prior journals ended without a system shutdown, OOM, or panic record; pstore was empty. Last battery-only sample was 35%, 3.546 V, discharging at 1.677 A, charger offline. On external power the device ran more than 44 minutes without another observed reboot. Power loss under load remains a hypothesis, not an established root cause. GNOME also logged vc4 swiotlb allocation failures during remote-display connections.

The physical keyboard and trackball were absent from Linux input devices. USB listed only LeafLabs Maple DFU 1eaf:0003. USB reset, DFU detach, and a shared-hub power-cycle request did not restore HID mode. Official application recovery restored 1eaf:0024, ClockworkPI uConsole Keyboard, ClockworkPI uConsole Mouse, and ttyACM0. The owner confirmed both physical keys and trackball work after recovery.

Archive: Bin/uconsole_keyboard_flash.tar.gz
Application inside archive: uconsole_keyboard_flash/uconsole_keyboard.ino.bin
Application size: 33920 bytes
SHA256: 277275d949e0ade09a215deb449dc847190577df98cb1ad162dec44aebd7868b
Verified archive Git blob against upstream tree before extracting.

The loose Bin/uconsole_keyboard_flash/uconsole_keyboard.ino.bin at that revision is a 65536-byte combined image with a reset vector below 0x08002000. Do not write that loose file at alternate setting 2. The verified archive application starts at 0x08002000; its reset vector is 0x080050f1.

Recovery command for the exact keyboard already in DFU:

```sh
sudo dfu-util -d 1eaf:0003 -a 2 -D /path/to/verified/archive/application.bin -R
```

The transfer reported 33920 bytes downloaded, manifestation status OK, and reset. Exit code was 74 despite those messages. Actual HID/serial re-enumeration, rather than exit code alone, proved runtime recovery. Never automatically flash on every reconnect. Installed diagnostic utilities: dfu-util 0.11-3build1 and uhubctl 2.6.0-3 from Ubuntu.

Do not run both exclusive consumers at once. ADS-B received 409 valid messages during the initial automatic-gain run, but reception was intermittent and aircraft were not continuously tracked. No simulated targets were used.

No kernel or desktop packages changed. hardware/aio-v2/meshtastic-lora.yaml is installed in /etc/meshtasticd/config.d/hakc-aio-v2.yaml; meshtastic-local.conf is the systemd drop-in. The service is enabled. The owner confirmed the LoRa antenna attached. SX1262 initialization succeeded over SPI1, IRQ26, Busy24, Reset25. The vendor aiov2_ctl LORA on command starts meshtasticd itself: never use it in that daemon's ExecStartPre. The drop-in instead raises verified GPIO16 using pinctrl. ## GPS

Legacy uconsole-4g-cm4.service ran after the AIO preparation and changed GPIO15 from UART receive to output. It also manipulates GPIO24, conflicting with LoRa Busy. Disabled its future startup without executing its GPIO-changing ExecStop. On this AIO V2 configuration, keep the legacy 4G startup disabled because those GPIOs are assigned to GPS and LoRa. This is not a blanket change for devices using the original 4G expansion board. Restored GPIO15 alternate function 5, after which valid NMEA arrived.

The GPS reported `$GPTXT,01,01,01,ANTENNA OPEN*25`, zero satellites, and fix mode 1. The owner will inspect the GPS antenna connection. No valid position was available to center the aircraft map. Do not substitute a guessed location or claim the default map center is GPS-derived.

## Aircraft decoder comparison

Ubuntu readsb 3.16-2build1 was downloaded with APT and extracted under ~/uconsole-tools/readsb-test/extracted without installing its system service. Its dependencies were already available. At 22:23 UTC the transient duo-adsb unit switched to this binary with --device-type rtlsdr --gain auto and the same local JSON directory. The original dump1090 package remains installed. Initial samples contained no valid aircraft messages; this change is a running reception comparison, not proof of improved RF performance. The map's older client may require field compatibility work if readsb becomes the permanent decoder.

At 22:23 UTC uptime was 51 minutes; battery was discharging, 3.548 V. The owner was told this was close to the pre-outage voltage reading and to retain external power for the demo.
